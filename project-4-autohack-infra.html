BACKGROUND

01 프로젝트 개요

AUTO HACK 2026은 차량 T-Box, EV 충전기, IVI, CAN 등 자동차 보안 문제를 다루는 CTF 대회입니다.
2026.11.17 ~ 11.20 광주에서 열린 본선(10팀)의 서버 인프라와 참가자·운영진 대시보드를 맡았습니다.


1. 팀마다 독립된 문제 환경 — 같은 문제라도 팀끼리 서로 간섭하지 않는 인스턴스가 필요
2. 일반 CTF와 다른 채점 방식 — 팀별 플래그, IDS 채점, 현장 스태프 판정처럼 CTFd 기본 기능으로는 안 되는 채점
3. 3일간 멈추면 안 되는 운영 — 장애 감지, 백업, 대기 서버 전환까지 미리 준비

03 시스템 구성

참가자 → 대시보드 (server1)
참가자 브라우저 nginx (TLS · 보안 헤더) CTFd + 커스텀 플러그인 MariaDB / Redis 문제 · 채점 · 점수판
문제 인스턴스 (server2)
문제 창에서 켜기 CTFd → k3s API (전용 RBAC) 팀 네임스페이스에 Pod 생성 WireGuard VPN으로 접속 60분 뒤 자동 종료
운영 · 장애 대비
watchdog 30초 점검 Slack/Discord 알림 · 자동 재시작 5분 단위 DB 백업 → server2 server3 대기 서버로 전환

팀 격리 (k3s)

영역구성
네임스페이스팀마다 별도 네임스페이스(team01~10 + 시험용 유령 팀), Kustomize overlay로 같은 규칙 적용
자원 제한ResourceQuota · LimitRange로 팀별 CPU/메모리 상한, 팀 상태 폴더 용량 감시
네트워크NetworkPolicy로 팀 간 통신 차단, 문제 포트 방화벽, VPN 방화벽
권한CTFd에는 인스턴스 켜기·끄기에 필요한 권한만 준 ServiceAccount(RBAC), 일부 문제는 seccomp · AppArmor 적용
KEY FEATURES

04 핵심 기능 — CTFd 플러그인

1. 팀별 인스턴스 문제 창에서 팀 전용 인스턴스를 켜고 끔. 참가자는 지금 볼 수 있는 문제의 인스턴스만 다룰 수 있고, 일시정지·대회 시간을 검사
2. 팀별 플래그 · 스태프 판정 채점 팀마다 다른 플래그를 넣고, 다른 팀 플래그를 내면 기록. 플래그 없이 현장에서 판정하는 문제는 관리자 채점 표에서 처리
3. IDS 채점 · 대회 타이머 IDS 문제 전용 화면·랭킹과 중계 API, EVSE·IVI·CAN 구간별 타이머를 대시보드에 연결
4. 정보 노출 차단 다른 팀 화면·팀 API 차단, 계정·팀 정보 변경 막기, 제출 내역 숨김
5. 이미지 기반 배포 main에 올리면 GitHub Actions가 시험 후 대시보드 이미지를 GHCR에 올리고, 서버는 커밋 해시 태그로 고정해 반영·되돌리기
SECURITY REVIEW

05 대회 전 보안 점검

서버·네트워크 관점과 참가자 우회 관점으로 나눠 점검하고, 찾은 문제를 고친 뒤 시험으로 확인했습니다.

발견조치
숨긴 문제의 인스턴스도 참가자가 켤 수 있음볼 수 있는 문제에 연결된 인스턴스만 허용, 전체 목록 API는 운영진 전용 (보안 시험 16/16)
참가자가 계정 이름·이메일을 바꿔 팀원을 잠글 수 있음CTFd 설정 + 플러그인에서 이름·이메일·비밀번호·팀 정보 변경 차단
관리 비밀번호가 sudo 기록을 거쳐 로그 수집기에 평문으로 들어감비밀번호 교체, 표준입력으로만 전달, Promtail에서 명령줄 가림
제출한 플래그 원문이 로그로 수집됨Promtail이 제출 문자열을 가림
Secure 쿠키·HSTS 없음, 지원 끝난 nginx, 약한 TLS 암호보안 헤더 추가, nginx 1.28, TLS1.2는 ECDHE+GCM/CHACHA20만 허용
DB 덤프 권한 0644, 비밀번호가 명령줄에 노출umask 077 · MYSQL_PWD 사용, 기존 사본 권한 600
OPERATIONS

06 장애 대응 · 운영 자동화

01
감시

두 서버의 systemd watchdog이 30초마다 컨테이너·Pod·디스크·인증서·서로의 서버 상태를 확인하고,
같은 문제는 10분에 한 번만 알림

02
자동 복구

멈춘 서비스는 재시작하되, DB·캐시는 쓰던 요청이 끊기지 않도록 알림만 보내고 사람이 판단

03
점검 모드

복구 중에는 표시 파일로 watchdog과 백업을 멈춰, 반쯤 복구된 DB가 켜지거나 최신 백업을 덮어쓰지 않게 함

04
대회 초기화

미리보기 → 승인 → 백업 → 실행 순서의 초기화 스크립트로 시연 기록만 지우고, 실제 문제는 보호 목록으로 막음.
최근 백업이 15분보다 오래됐거나 대회가 이미 시작됐으면 스스로 멈춤

TAKEAWAYS

07 배운 점

• 실제 사용자가 있는 운영 — 10팀이 3일간 쓰는 서비스를 직접 운영하며, 기능보다 감시·백업·되돌리기 경로를 먼저 갖추는 것이 중요하다는 걸 체감
• 공격자를 참가자로 둔 설계 — 참가자 전원이 해커라는 전제로 권한·격리·로그를 설계하고, 남은 설계 한계(팀별 IP 부재 등)는 운영 규칙과 공지로 보완
• 기록이 남는 변경 관리 — 서버 상태와 저장소를 일치시키는 규칙과 인계 문서 덕분에 대회 중에도 변경 이력을 추적 가능
